# Ember / Crucible 临时修补

针对 **Crucible 0.10.1** 与 **Ember 0.6.0** 上游若干数据/逻辑缺陷的运行时补丁。

**全部是运行时修补，不写世界存盘数据。** 停用模块 → 刷新 → 恢复原状。
每一项都能单独关掉，也可以在控制面板里一键全关。

---

## 安装

Foundry「配置与设置 → 附加模块 → 安装模块」，在最下面的 **Manifest URL** 里粘贴：

```
https://github.com/takaqiao/ember-crucible-tempfix/releases/latest/download/module.json
```

**依赖**：`crucible` 系统 ≥ 0.10.0。Ember 模块不是硬依赖 —— 没装 Ember 时相关条目不会命中任何东西。

---

## 控制面板

**配置与设置 → 模块设置 → Ember / Crucible 临时修补 → 打开控制面板**

一处看全：每条补丁此刻是否生效、一键自检、复制诊断报告、批量开关。
每个按钮旁边都写着**等价的控制台命令** —— 会用面板的不必学命令，要写宏的可以直接抄。

| 按钮 | 等价命令 | 效果 |
|---|---|---|
| 运行自检 | `emberCrucibleTempFix.diagnose()` | 逐条列出补丁**此刻**的真实状态：包装上没有、开着还是关着、命中了哪些动作。选中 token 会连角色一起查 |
| 复制诊断报告 | `copy(emberCrucibleTempFix.diagnose())` | 把自检结果连同系统 / Ember / 模块版本复制到剪贴板。**报 bug 时先点这个** |
| 重新准备角色数据 | `emberCrucibleTempFix.reprepareActors()` | 让刚改的开关立刻作用到已打开的角色卡。**不写盘** |
| 全部开启 | — | 把所有开关打开（这也是默认状态） |
| 全部关闭 | — | 行为回到**上游原样**。用来对照「这现象是不是本模块引起的」，不必停用模块刷新 |

另有两个只在控制台的：

| 命令 | 效果 |
|---|---|
| `emberCrucibleTempFix.help()` | 打印上面这张命令表 |
| `emberCrucibleTempFix.openPanel()` | 直接打开控制面板 |

面板里每条补丁有三种状态：**生效中** / **已关闭** / **上游已修**
（最后一种是开关还开着，但检测到上游版本已经修好了这条，于是自动让路 —— 这是正常的）。

## 目前状态

| | |
|---|---|
| 补丁数 | **32** |
| 离线断言 | **280 条**（`node tests/tempfix_harness.mjs`） |
| 变异测试 | **36/36**（`node tests/mutate.mjs`，把补丁改回坏写法，验断言真的会红） |
| 真实牌桌验证 | **1 条** |

**已被现实证实的**：N10 —— 实测「强健体力」用了没任何效果、1 专注 + 1 点英雄气概白扣，与诊断逐字吻合。

**其余 31 条只有静态取证 + 桩件断言**，还没在真实牌桌上逐条走过。
注意即使是 N10，被证实的也只是「**缺陷存在**」，「补丁修好了它」仍待验证 —— 两件事分开记。

逐条的验证方法见 [`HANDOFF.md`](HANDOFF.md) §3，每行都标了设置键名，可机械核对覆盖率。

### 已知不做的

- **C6**（蒸汽喷口半径）—— 是平衡决策，不是缺陷。
- **E3**（混沌折射恩惠骰）—— 需要一条无法验证的持久化通道。
- **`waterAversion`（畏水 Water Aversion）缺掷骰实现** —— 它自己的描述里写着「ALPHA ONE: This action needs further balancing」，是作者挂着的半成品，不是漏了实现。
- **N2 的第三条加成（威吓 +2 恩惠骰）** —— 系统层面表达不了，恩惠骰读取点是全局的、无法按技能限定。

## 注意事项

- **已经生成的聊天卡里存着当时的动作快照。** 停用模块不会改写旧卡，旧卡再点确认仍按当时的行为结算。这是唯一一处「停用后不能完全恢复原状」的地方。
- **N2 与 E2 依赖 N10。** 它们的效果同时还因时长单位非法而根本不会被创建，两个开关都开着才有意义（默认都开）。
- **N10/N12 是解释而非还原。** 上游没有 `turns` 这个单位，原作者想要多久无从考证；本模块按上游自己迁移同类数据时的映射处理，数值不变。
- **X1 补的是实现不是数值。** 防御、伤害类型、属性加值全部读自动作自己的标签，本模块不发明任何数字。
- **与 crucible 自带的 Ember 兼容层不冲突** —— 那一层按 Ember 版本闸门跑，本模块的条目与它不重叠。
